# Nature Remo - Home Assistant カスタム統合

⭐ この統合が役に立った場合は、GitHubでスターを付けていただけると嬉しいです。

Nature RemoをHome Assistantに連携するためのカスタムインテグレーションです。  
エアコンや照明の操作、温度・湿度などの情報をHome Assistant上でまとめて扱えるようになります。

---

## ⚠️ ご注意
このカスタムインテグレーションは、Nature社およびHome Assistantの**非公式**な統合です。  
利用にあたっては、**自己責任で**ご使用いただきますようお願いいたします。

---

## 主な機能

- Nature Remoに登録された家電（エアコン・照明）の操作
- 温度・湿度・照度・人感センサーのデータ取得
- Nature Remo E / E Liteによるスマートメーターの電力データ取得
- エコキュートの状態・積算電力量・残湯量を監視
- カスタムサービスによる照明の詳細な制御（モード指定など）
- signals に基づいて生成されたリモートエンティティを使って IR コマンドを送信
- 学習済みの IR 信号をダッシュボードのボタンで送信

## インストール方法（HACS）

以下のボタンをクリックすると、HACSにこのリポジトリを簡単に追加できます。

[![Open your Home Assistant instance and open the repository inside the Home Assistant Community Store.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=NaNaLinks&repository=homeassistant_nature_remo&category=integration)

1. Home AssistantでHACSを開きます
2. 右上のメニュー（⋮）をクリックします
3. 「Custom repositories」を選択します
4. 以下のリポジトリURLを追加します  
   https://github.com/NaNaLinks/homeassistant_nature_remo  
   カテゴリは「Integration」を選択してください
5. 「Nature Remo」をインストールします
6. Home Assistantを再起動します

## インストール方法（手動）

1. 本リポジトリを以下のパスに配置してください：

```
<設定フォルダ>/custom_components/nature_remo/
```

2. Home Assistantを再起動してください。

## セットアップ手順

1. Home Assistantの「設定 → デバイスとサービス → 統合を追加」から `Nature Remo` を選択します。
2. アクセストークン（APIキー）と統合の名前を入力します。
   - トークンは [Nature公式サイト](https://home.nature.global) から発行できます。
3. 登録済みのデバイスや家電が自動的に追加されます。

同じ Nature アカウントは、別のアクセストークンを使っても1回だけ登録できます。再認証には同じアカウントのトークンを使用してください。既存の重複登録は **設定 → システム → 修理** に通知されるので、1つだけ残してほかを削除してください。自動では削除しません。

---

## オプション設定

- 更新間隔は 30・60・90 秒から選択できます（既定は 60 秒）。
- Remo 本体を選択すると、その本体の設定セクションを開きます。外部温度・湿度の欄はエアコンが接続された本体にだけ表示します。
- 保存後は自動で統合を再読み込みして反映します。更新間隔だけを変更する場合は、本体を未選択にします。

⚠️ Nature Remo Cloud API にはリクエスト制限があります。  
更新間隔を短く設定しすぎると、APIの制限に達する可能性があります。

## 対応エンティティ一覧

| 種類    | 説明                                                              |
|---------|-------------------------------------------------------------------|
| climate | エアコンの操作（冷房・暖房・除湿など）                           |
| binary_sensor | 人感検出、エコキュートの動作状態 |
| number | 対応するエアコンの自動・除湿の温度補正 |
| light   | 照明の操作（オン／オフ、モード切替）                              |
| sensor  | 温度、湿度、照度、最終検出時刻、電力（買電／売電）、外部センサーの中継、エコキュートの電力量・残湯量・モード |
| remote  | IR／AC／LIGHT の学習信号と TV のプリセット・学習信号を送信 |
| button | 家電の種類を問わず、学習済み信号を個別に送信 |

※ 今後、さらに対応デバイスやエンティティを拡張予定です。

## v0.3.0 への移行

家電ごとにデバイスを作成し、Remo 本体を親として関連付けます。本体の温度・湿度・照度・人感は引き続き Remo 本体に残ります。エンティティ ID は維持します（下記の人感のドメイン変更を除く）が、**デバイス単位の自動化とエリアの割り当ては設定し直しが必要です**。内蔵センサーのない Remo E も親デバイスとして残ります。

人感センサーを `sensor.<object_id>` から `binary_sensor.<object_id>` に移します。object_id とユーザー設定の名前・アイコン・エリア・無効化・非表示を引き継ぎ、旧レジストリエントリを削除します。新しい ID が既に使われている場合は Home Assistant が空いている ID を選び、修理通知に実際の対応を表示します。

自動化・スクリプト・ダッシュボードの参照を新しい `binary_sensor.` の ID に書き換えてください。**設定 → システム → 修理**に変更された ID の一覧が出るので、更新後に通知を閉じてください。最終検出時刻のセンサーは ID を変えずにタイムスタンプを返すようになります。

## エアコンの操作

エアコンは v2 API で操作し、機種が対応している風量・上下スイング・左右スイングを表示します。温度単位は家電の設定に従います。

- 停止中のエアコンをオンにすると、必ず**自動モード**で起動します。運転中のオン操作では何も送りません。自動モードがない機種ではオン操作を表示しないので、対応する運転モードを指定してください。
- 相対温度を使う自動・除湿モードには、**温度補正** number（-3〜+3、0.5刻み）を追加します。他のモードや停止中は利用できません。このとき climate に絶対値の目標温度は表示しません。
- 自動で起動するときは、最後に確認できた補正値を使います。操作が成功した応答を受けてから両エンティティを更新します。

---

## 照明のモード

`nature_remo.send_light_mode` の `entity_id` に照明、`mode` に対応するボタン名を指定して操作できます。複数アカウントを登録している場合も、呼び出すたびに照明の所属先を確認します。無効・未読み込み・存在しない照明や未対応モードは、送信前にエラーになります。状態は送信に成功した後だけ更新します。

応答データを要求した場合の形式は、従来どおり `{"status": "success", "appliance_id": "..."}` です。

## 学習済み信号のボタン

Remo アプリに登録した信号ごとに、信号名のボタンを家電デバイスへ追加します。IR・AC・LIGHT・TV のすべてが対象です。ダッシュボードや `button.press` から送信でき、既存の remote エンティティも引き続き使えます。信号を追加したら統合を再読み込みしてください。

エアコンの「内部クリーン」なども、Remo アプリでその操作を信号として学習させれば送信できます。API の `extras` はエンティティにしていません。送信に失敗すると Home Assistant にエラーが表示されます。

サーキュレーターや KVM など状態を取得できない家電は、この押しボタンを通常の操作に使ってください。「電源」という信号名だけではオン・オフ専用か切替かを判定できないため、動作が確認できるまで一律に改名しません。

新規の汎用学習信号 `remote` は既定で非表示になりますが、既存スクリプトや `remote.send_command` から利用できるよう有効なままです。状態は送信成功後も常に `unknown`（不明）です。`last_command` 属性はその remote から最後に送信に成功したコマンドを記録し、従来の `command` 属性も同じ値を返します。どちらも実機状態を保証せず、ボタンや他のリモコンからの操作は記録しません。再起動・再読み込みでこれらの属性はクリアされます。旧 remote の状態をコマンド履歴として使う自動化は `last_command` へ変更してください。実際の電源状態を判定するには、別の状態取得元が必要です。

既存の表示中 remote には、設定 → システム → 修復に **学習IR機器の操作をボタン中心に変更** を表示します。非表示にする remote を選択し、選択しなかったものは表示を維持します。変更するのは表示だけで、エンティティ ID・名前・エリア・無効化設定・コマンド送信機能は維持します。選択は記憶され、エンティティ設定から再表示もできます。既に非表示・無効な remote はその設定を維持します。機器設定ページや詳細ダイアログには、非表示の remote でも電源操作が残ります。HA にはこれらを remote ごとに消す機能がありません。非表示が適用されるのは自動生成ダッシュボードです。手動で配置したダッシュボードのカードは、別途信号ボタンに置き換えてください。状態を不明にしたりエンティティを非表示にしたりしても、カード自体は書き換わりません。TV remote と climate/light 専用操作の動作は変わりません。

## サンプル：リモートエンティティの使い方

Nature Remoに定義された `signals` 情報をもとに `remote` エンティティが生成されます。  
Home Assistant上から `remote.send_command` を使って信号を送信できます。

信号名の大文字小文字は区別しません。`remote.turn_on` には `on` または `オン`、`remote.turn_off` には `off` または `オフ` という専用信号が必要です。対応する信号がなければ送信前にエラーを返します。「電源」を代わりに送ることはありません。電源切替信号だった場合、稼働中の家電に `turn_on` を呼ぶと逆に停止し得るためです。

### 例：サービス呼び出し

以下のように `remote.send_command` を使って信号を送信します：

```yaml
service: remote.send_command
target:
  entity_id: remote.living_room_remote  # リモートエンティティID
data:
  command: "電源"  # Remoに登録されたボタン名
```

## テレビのリモート操作

Remo に登録した TV ごとに、学習信号がなくても remote エンティティを作成します。`remote.send_command` ではプリセットのボタン名（`vol-up` など）、表示名、学習信号名を指定でき、大文字小文字は区別しません。不明なコマンドはエラーになります。`input` 属性は API の状態を表示し、操作の成功応答と通常のポーリングで更新します。

`power-on` と `power-off` が両方ある機種だけ、`remote.turn_on` / `remote.turn_off` を使えます。HA の共通 remote 操作は機種ごとに非表示にできないため、トグル電源だけの機種では未対応エラーを返し、送信しません。明示的に電源を切り替えるには `remote.send_command` で `power` を送ってください。電源状態は最初は不明で、離散操作後も推定値です。赤外線では実際の電源状態を確認できません。

TV の動作はモックで検証しています。以前使っていた REGZA 32ZP2 は現在使っていないため、実機では未検証です。今回は remote として提供し、media_player 機能はありません。

## エコキュートの読み取り

Remo E 経由のエコキュート（`EL_ELECTRIC_WATER_HEATER`）に、読み取り専用のセンサーを追加します。家電デバイスに次の値を表示します。

- 動作・沸き上げ中・給湯中の状態、昼間沸き増し許可、風呂自動モード
- 積算消費電力量（kWh、`total_increasing`）。エネルギーダッシュボードで利用可能
- 残湯量（L）、沸き上げ設定、風呂の動作状態

対応するプロパティのうち、最初に成功した応答に含まれたものだけをエンティティにします。対象機器があるときだけ、通常とは別の5分間隔で取得します。機器やプロパティの追加後は統合を再読み込みしてください。不正値・欠測は不明のまま扱い、正常なゼロは維持します。取得に失敗した場合は前回のデータを保持し、取得が成功するまで利用不可にします。起動時にエコキュート用 API が一時的に失敗しても他の家電は利用でき、初回取得が成功するとセンサーを自動で追加します。プロパティの更新日時から鮮度を判定せず、エコキュートを操作する機能も追加しません。

## 外部温度・湿度センサーの利用

エアコンが接続されている Remo 本体ごとに、外部の温度・湿度センサーを設定できます。

climate は中継センサーを通じて外部の温度・湿度を参照します。中継が未設定・利用不可・無効の場合は、対応する Remo 本体の値に戻ります。元のセンサーが復帰すると即座に反映します。

### 使い方

- Home Assistantの統合設定を開く
- Remo 本体を選択し、その本体の設定セクションに進む
- 温度・湿度のセンサーエンティティを選ぶ。選択を外すと内蔵センサーに戻る
- 保存すると、自動で再読み込みして設定を反映

設定したエアコンの家電デバイスに、**外部温度**・**外部湿度**の中継センサーも追加されます。元の値、device_class、state_class、ネイティブ単位を引き継ぎ、API の呼び出しは増やしません。元の状態が変わると即座に更新し、元が存在しない場合や数値でない場合は利用不可になります。初期表示単位は元に合わせ、その後は HA の単位設定で変更できます。

設定後は、以下に反映されます：

- climateエンティティの温度・湿度表示
- エアコン制御に使用される環境データ

### 注意事項

- 外部センサーが未設定、または中継が利用不可の場合は Remo 本体の値を使います。本体の値もない場合は不明になります。
- 存在し、有限の数値を持つセンサーを選択してください。温度の単位は °C または °F、湿度は % が必要です。
- 循環参照を避けるため、元のセンサーを選んでください。Nature Remo の中継センサーは選択できません。
- 更新前の外部センサー設定は引き継がれます。一台の設定を変更しても、他の本体の設定は維持します。
